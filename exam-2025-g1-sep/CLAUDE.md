# HYPER ACADEMY 시험대비 변형문제 제작 — 작업 지시서

이 폴더는 하이퍼 학원(HYPER ACADEMY, 경기도 안산) 원장님의 **영어 모의고사 시험대비 변형문제** 제작 작업장이다.
원장님이 "2025 고1 9월 29번 만들어" 같은 지시를 하면, 아래 절차와 `기준/출제기준.md`를 **그대로** 따라 교재를 만든다.

## 0. 가장 중요한 원칙 (반드시 지킬 것)

**[2026-10-02 개정 — 시험대비 교재 레이아웃·결과물 규칙 (원장 확정, 아래가 우선)]**
모양 기준: `기준/샘플_머릿말형_2025고1_9월_29번.pdf` (이 모양과 똑같아야 한다).
- **상단 밴드**(HYPER ACADEMY · 교재명 · 지문번호)는 각 지문의 **시작 쪽에만** 넣는다. 합본이면 지문마다 시작 쪽에 다시 넣는다.
- 나머지 쪽은 밴드 대신 **머릿말**: 가는 선(0.8pt 네이비) + 오른쪽 끝에 그 쪽의 문제 유형 이름(8.5pt 굵게 네이비), 선 오른쪽 끝에 주황 포인트(폭 14mm, 높이 1.8pt).
  한 쪽에 두 유형이 걸치면 "글의 제목 · 글의 주제"처럼 둘 다 표시. 밴드가 빠진 쪽은 머릿말(8.5mm)만큼 본문 영역이 넓다.
- **공식 템플릿**: `템플릿/시험대비_템플릿.html`이 학원 영어 교재 제작 공식 템플릿이다(2026-10-02 확정, 다시 수정하지 않는다). 앞으로 만드는 모든 영어 교재(시험대비 교재·수업자료)는 이 템플릿을 그대로 쓴다.
- 꼬릿말: 왼쪽 하이퍼 영수 전문학원, 오른쪽 24시간 학습을 설계하다, 둘 다 네이비 굵은 글씨
- 모든 작업은 꼭 필요한 작업만 한다. 지시하지 않은 확인·검증·수정·부가 작업은 하지 않는다.
- 한 쪽 2문항, 넘치면 1문항, 남는 공간 1:1:1 배분은 그대로. 오른쪽 세로 강조선·색·여백·글꼴도 그대로.
- **결과 폴더에는 PDF만 저장한다** (시험대비 교재·수업자료·단어장 모두). HTML은 PDF를 만들기 위한 중간 파일이며, 스크립트가 PDF를 열어 확인한 뒤 자동으로 지운다.
  (확인 항목: 쪽수 일치·꼬릿말 존재·본문이 꼬릿말을 넘지 않음·문제지에 정답 없음. 문제가 있으면 HTML을 남기고 경고한다. `pymupdf` 필요.) 작업 폴더의 JSON(문제 데이터)은 절대 지우지 않는다.
- **문제지에는 정답·해설을 붙이지 않는다. 정답지는 별도 PDF이며, 시험 전체 합본의 정답지 하나만 만든다 (2026-10-02 원장 확정). 개별 번호(지문)의 정답지는 만들지 않는다.**
  - 이름: 개별 문제지 `{시험}_{번호}번.pdf` (정답지 없음) / 합본 문제지 `{시험}_시험대비_변형문제.pdf` + 합본 정답지 `{시험}_시험대비_변형문제_정답지.pdf`
  - 정답지 첫 쪽 밴드의 오른쪽 칸은 "정답", 내용(정답표·해설·모범답안·채점)은 기존 정답 쪽과 같다. 둘째 쪽부터 머릿말은 "정답 및 해설".
  - 수업자료도 같은 방식: 학생용(수업 노트·확인 테스트) `…_수업자료.pdf` + 정답지 `…_수업자료_정답지.pdf`.
- 이 개정은 앞으로 만드는 것부터 적용한다. 결과 폴더의 기존 결과물(HTML 포함)은 지우거나 바꾸지 않는다(스크립트의 중간 파일은 `__작업중` 이름이라 기존 파일과 겹치지 않는다).
- 템플릿·스크립트의 개정 전 원본은 같은 폴더에 `_백업_20261002` 이름으로 보관(`템플릿/시험대비_템플릿_백업_20261002.html`, `스크립트/*_백업_20261002.py`, `CLAUDE_백업_20261002.md`).

**[최우선 원칙] (2026-09-26 원장 확정)** 앞으로 제작하는 모든 지문의 교재는 `기준/샘플_2025고1_9월_29번.html`과
형식·구성·품질이 동일해야 한다. (유형 구성과 순서, 유형당 3문항, 서술형 9문항 구성, 발문·선지 형식,
정답·해설 방식, 디자인, 글자 크기 10pt 모두 동일)

샘플과 다르게 하는 것은 **오직 두 가지뿐**이다:
1. 용지 여백: 상하 5mm, 좌우 10mm
2. 한 쪽에 2문제가 원칙이되, 요약문처럼 2문제가 A4를 넘치는 경우에만 그 쪽을 1문제로 배치
   (판단은 스스로 하고 — `교재_조립.py`가 자동 처리 — 보고에 어느 쪽을 1문제로 했는지 적을 것)
   - 2문제 쪽은 남는 세로 공간을 ① 밴드~문제1 ② 문제1~문제2 ③ 문제2~쪽 하단, 이 세 구간에 **1:1:1로 똑같이** 나눠 쪽 전체를 채운다(하단 여백 최소화, 스크립트가 flex space-evenly로 자동 처리). 1문제 쪽은 위에서부터 배치한다(억지로 늘리지 않음).
   - 현재 `기준/샘플_…29번.html`은 이 두 가지가 반영된 버전이다(2026-09-26 교체, 1:1:1 분배로 재교체).

이 두 가지 외에 샘플과 다르게 만들어야 할 이유가 생기면, **임의로 바꾸지 말고 먼저 원장에게 물어라.**

1. **품질 기준은 `기준/샘플_2025고1_9월_29번.html`과 `.json`이다.** 대화를 시작할 때 1회 읽고, 같은 수준·같은 형식으로 만든다(지문마다 다시 읽지 않는다).
2. **지문은 원문 그대로 쓴다.** HWP에서 추출한 영어 본문만 쓰고, 해석은 절대 쓰지 않는다. 지문을 지어내거나 요약해서 바꾸지 않는다(문제 형식상 필요한 변형만 허용: 밑줄·빈칸·삽입 위치·어휘 교체 등).
3. **유형당 3문항, 샘플과 동일이 원칙. 억지 문제는 만들지 않되, 줄이는 것은 원장님이 정한다.** (2026-09-26 원장 확정)
   - 지문 성격상 3문항이 억지스러운 유형이 있으면 **임의로 줄이지 말고 원장님께 먼저 묻는다.**
   - 단, 여러 지문을 한꺼번에 작업할 때는 멈추지 말고 **그 유형만 비워 둔 채 나머지를 진행**하고, 작업이 끝난 뒤 해당 지문·유형·이유를 **한꺼번에 모아서** 묻는다.
4. **HTML은 손으로 쓰지 않는다.** 문제는 JSON으로 작성하고 `스크립트/교재_조립.py`로만 HTML을 만든다(템플릿 디자인이 깨지지 않게).
5. **모든 객관식은 직접 다시 풀어서 정답이 하나로만 떨어지는지 확인한다.** 애매하면 고치거나 버린다.
   - **정답 기준은 무조건 원문이다 (2026-09-26 원장 확정).** 삽입의 정답은 빼낸 문장이 원래 있던 위치, 순서의 정답은 원문 순서다. "다른 위치·다른 순서도 말이 된다"는 이유로 문항을 빼거나 줄이거나 "검수 필요"로 표시하지 않는다. 해설에는 원문 위치를 뒷받침하는 단서를 적는다.
   - 내가 직접 만드는 오답 선지(빈칸·연결사·요약문·대의 파악 등)는 지금처럼 정답과 겹치지 않게 만든다.
6. 원장님은 직설적이고 정직한 답을 원한다. 못 하는 것은 못 한다고 말하고, 지시가 불합리하거나 불필요하면 **이의를 제기하고 대안을 제시**한다. 확신이 없는 문제는 숨기지 말고 보고서에 "검수 필요"로 표시한다.
7. 원장님과는 한국어로, 간결하고 구조적으로 소통한다.
8. **검증은 확정된 원칙대로 최소한만 한다 (2026-09-26 원장 확정).**
   - **작업 시작할 때 1회만**: CLAUDE.md, `기준/출제기준.md`, `기준/샘플_2025고1_9월_29번.json`을 대화에서 처음 한 번만 읽는다. 이후 지문마다 다시 읽거나 샘플과 대조하지 않는다.
   - **지문마다 하는 일 — 이것만 한다**: ① `작업/{시험}_지문.json`에서 해당 번호 지문을 가져온다(없으면 `hwp_추출.py` 1회 실행) ② 샘플과 똑같은 구조·유형 순서·문항 수로 문제 JSON을 작성한다(만들면서 직접 풀어 정답이 하나인지 확인 — 별도 재검토 단계 없이) ③ `교재_조립.py` 1회 실행, 경고가 나오면 그 부분만 고치고 1회 재실행.
   - **하지 않는 것**: 기준·샘플 재검토, 샘플과의 반복 비교 대조, 같은 파일 반복 조립·렌더링, PDF 출력, 쪽별 높이 측정, 확정된 원칙을 원장님께 다시 묻는 것, 긴 분석·설명.
   - **보고는 지문마다 3줄 이내**: 결과 파일명 / 문항 수 / 1문제 배치 쪽 — 정답이 애매해 원장님이 봐야 할 문항이 있을 때만 번호와 이유 한 줄 추가.
   - **여러 지문을 시킬 때**: 지문 하나 끝낼 때마다 멈추지 말고 다음 지문으로 넘어간다. 성립하지 않는 유형은 비워 두고 진행한 뒤, 모든 작업이 끝나고 한꺼번에 보고한다.

## 1. 폴더 구조

```
클로드 변형/
├─ CLAUDE.md                  ← 이 문서
├─ 처음_시작하기.txt           ← 원장님용 안내
├─ 기준/
│   ├─ 출제기준.md             ← 유형별 출제 규칙·모의고사 분석·검증 체크리스트 (반드시 숙지)
│   ├─ 샘플_2025고1_9월_29번.json   ← 품질 기준 데이터 (JSON 작성 예시)
│   └─ 샘플_2025고1_9월_29번.html   ← 품질 기준 완성본
├─ 템플릿/시험대비_템플릿.html  ← HYPER 공식 템플릿 (수정 금지)
├─ 스크립트/
│   ├─ hwp_추출.py             ← HWP → 번호별 영어 지문 JSON
│   └─ 교재_조립.py            ← 문제 JSON → 문제지·정답지 PDF + 자동 검증
├─ 입력/   ← 원장님이 HWP 원본(백지노트 형식)을 넣는 곳
├─ 작업/   ← 지문 JSON, 지문별 문제 JSON (중간 결과)
└─ 결과/   ← 완성 교재 PDF (문제지 + 정답지, 2026-10-02부터 HTML은 남기지 않음)
```

## 2. 작업 절차 (지문 1개 기준)

**① 지문 추출** — 해당 시험의 `작업/{시험}_지문.json`이 없으면 먼저 만든다.
```
py 스크립트/hwp_추출.py 입력/<파일명>.hwp 2025고1_9월
```
- 시험 이름 규칙: `2025고1_9월`, `2026고2_9월` 처럼 붙여 쓴다.
- 추출 결과 목록에 ⚠ 경고가 있거나 단어 수가 이상하면 원본과 대조해서 바로잡는다. 추출이 실패하면 원장님께 알리고 멈춘다.

**② 지문 분석** — 지문 번호로 원래 유형을 확인하고(3장 표) 제외할 유형을 정한다. 지문의 주제문, 논리 구조(대조·예시·인과), 대명사·연결사 위치, 핵심 어휘를 먼저 정리한다.

**③ 문제 작성** — `작업/{시험}_{번호}번.json`에 작성한다. 형식은 `기준/샘플_2025고1_9월_29번.json`과 똑같이.
- 번호에 물결이 있으면 파일명은 `2025고1_9월_41-42번.json`처럼 하이픈으로 쓴다.

**④ 자체 검증** — 만들면서 직접 풀어 정답이 하나인지 확인한다(0장 원칙 8). 별도 재검토 단계를 두지 않는다.

**⑤ 조립·자동 검증**
```
py 스크립트/교재_조립.py 작업/2025고1_9월_29번.json
```
- 조립은 1회. "[확인 필요]"가 나오면 그 항목만 고치고 다시 조립한다.
- 페이지 배치는 스크립트가 자동으로 한다(5장 "페이지 배치 원칙"). "1문제만 두어도 A4를 넘침" 경고가 나오면 원장님께 보고한다(내용 삭제·축약으로 해결하지 않는다).
- playwright가 없으면 자동 배치·넘침 확인이 생략된다. 원장님께 알리고 `py -m pip install playwright` 및 `py -m playwright install chromium` 설치를 제안한다.
- **결과는 PDF로만 남는다** (2026-10-02 개정, 위 개정 블록 참고). `교재_조립.py`가 문제지 PDF와 정답지 PDF를 만들고 각각 열어 확인한 뒤 중간 HTML을 지운다(A4, 배경 그래픽 포함, 템플릿 `@page` 여백 그대로, playwright 필요). `--out 폴더`로 저장 위치를 바꿀 수 있다(확인용). 기존 결과물을 PDF로 다시 뽑을 때만 `py 스크립트/pdf_출력.py <html경로...>`.

- **문제지(번호별·합본 모두)에는 정답 및 해설 쪽을 넣지 않는다.** 정답은 합본 정답지 PDF 하나로만 제공하고, 번호별 `…_정답지.pdf`는 만들지 않는다(2026-10-02). 시험 1회분을 끝내면 `--merge`로 합본 문제지 + 합본 정답지를 함께 만든다.

**⑥ 보고** — 지문마다 3줄 이내: 결과 파일명 / 문항 수 / 1문제로 배치한 쪽(없으면 "없음"). 정답이 애매해 원장님이 봐야 할 문항이 있을 때만 번호와 이유 한 줄 추가.

### 여러 지문을 한꺼번에 지시받은 경우
- 지문마다 ①~⑤를 반복하고, 각 지문 JSON을 따로 저장한다. **지문 하나 끝낼 때마다 멈추지 말고 다음 지문으로 넘어간다**(진행 중 보고 없이 계속 진행).
- 성립하지 않는 유형(3문항이 억지스러운 유형)이 나와도 멈추지 않는다. 그 유형만 비워 두고 나머지를 진행한 뒤, **모든 작업이 끝나고 한꺼번에** 지문·유형·이유를 모아 묻는다. 원장님 결정이 나오면 해당 JSON을 보완해 다시 조립한다.
- 시험 1회분이 끝나면 한 권으로 합친다:
```
py 스크립트/교재_조립.py --merge 2025고1_9월
```

> 이 PC에서는 `python` 명령이 동작하지 않으므로 `py`로 실행한다. 한글 경로 문제로 스크립트가 실패하면 원인을 보고하고 해결한다.

## 4. 한 지문의 문항 구성 (공식 기준)

**객관식 — 11개 유형 × 각 3문항 (제외 유형 빼고)**, 이 순서로 배치:
글의 제목 → 글의 주제 → 글의 요지 → 어법 → 어휘 → 빈칸 추론 → 글의 순서 → 문장 삽입 → 요약문 → 연결사 → 지칭 추론

**서술형 — 9문항**, 객관식 뒤에 배치:
배열 영작 3 → 어법 고치기 3 → 조건 영작 2 → 어순 배열(복문) 1

유형별 세부 규칙은 `기준/출제기준.md`에 있다. JSON의 `"type"` 값은 샘플과 같은 이름을 쓴다(어법은 `"어법"`).

## 5. 파일·표기 규칙
- 문제 JSON 필드: `exam, no, original_type, book, sub, foot, questions[]` — 샘플 JSON 참고.
  - `book`: "2025 고1 9월 모의고사 시험대비 변형문제" / `sub`: "29번 지문 · 어법 제외 유형별 변형 문항" / `no`: "29번"
  - `foot`: HWP 각주를 그대로 (없으면 빈 문자열)
- 지문 안 표기법(밑줄·빈칸·삽입 위치 등)은 `스크립트/교재_조립.py` 맨 위 설명을 따른다.
- **페이지 배치 원칙 (2026-09-26 원장 확정, 0장 최우선 원칙과 동일)**
  - 용지 여백: 상하 5mm, 좌우 10mm 고정 → 내용 높이 287mm (A4 넘침 기준)
  - 한 페이지당 2문제가 원칙. 2문제가 A4를 넘치는 쪽만 1문제로 배치하고, 남은 문제는 다음 쪽으로(스크립트가 자동 처리)
  - 2문제 쪽: 남는 세로 공간을 ① 밴드~문제1 ② 문제1~문제2 ③ 문제2~쪽 하단, 이 세 구간에 1:1:1로 똑같이 나눠 쪽 전체를 채운다(하단 여백 최소화, flex space-evenly). 1문제 쪽: 위에서부터 배치(억지로 늘리지 않음)
  - 금지: 줄 간격·박스 여백 축소, 글자 크기 10pt 변경, 지문·선지 내용 삭제나 축약, 템플릿 디자인(밴드·색·폰트) 변경
  - **꼬리말은 종이 끝에서 10mm 위(인쇄 잘림 방지, 2026-09-28 확정)**: 프린터의 인쇄 불가 영역 때문에 꼬리말이 종이 가장자리에 바짝 붙으면 실제 인쇄 시 잘린다. 템플릿의 `.ft-space`(13mm), `.page-foot` 테두리(.8pt), 화면용 `bottom: 10mm`, 인쇄용 `bottom: 5mm`로 5mm씩 위로 올려 두었다(`교재_조립.py`의 `FOOT_MM=13`, `수업자료_조립.py`의 `.note-wrap height:238mm`도 함께 맞춰 둠). 이 값들을 다시 8mm/5mm/0으로 되돌리지 말 것.
- 결과 PDF는 `결과/`에만 저장한다(HTML은 남기지 않는다). `템플릿/`과 `기준/` 파일은 수정하지 않는다(원장님이 기준 변경을 지시한 경우만 예외).

## 7. 수업 자료 형식 (2026-09-27 추가)

시험대비 변형문제와는 별개로, **수업용 자료**(문장별 필기 노트 → 어법 선택 확인 테스트 → 정답)를 만들 때 쓰는 형식이다.
스크립트: `스크립트/수업자료_조립.py` / 품질 기준: `기준/수업샘플_2026고1_9월_21번.json`·`.html`.

- 실행: `py 스크립트/수업자료_조립.py 작업/{시험}_{번호}번_수업.json` → 결과 `결과/{시험}_{번호}번_수업자료.pdf`(학생용: 수업 노트 + 확인 테스트, 정답 없음) + `결과/{시험}_{번호}번_수업자료_정답지.pdf`(정답지). HTML은 남기지 않는다.
- 구성: 학생용 PDF = ① 수업 노트(문장별 밑줄 노트, 175단어/12문장 넘으면 다음 쪽) ② 확인 테스트(문장 순서를 섞고 각 문장에 `[ A / B ]` 어법 선택 + 해석 줄 + 마지막에 원래 순서 배열 문제), 정답지 PDF = ③ 정답 및 해설(어법 선택 정답표 + 문법 포인트 + 문장 순서 + 모범 해석).
- JSON 필드: `book, no, foot, sentences[](text/ko/points/lines), shuffle, covered, absent, source_text`
  - `sentences[].text`: 원문 문장 안에 어법 선택 지점을 `[오답 / *정답]`으로 표시(정답 앞에 `*`, 오답·정답 순서는 매번 섞음). `*` 표시만 남기면 원문과 한 글자도 달라지면 안 됨(조립 스크립트가 `source_text`와 자동 대조).
  - 문장에 실제로 있는 문법 요소(to부정사·동명사·분사·관계대명사·관계부사·분사구문·수일치·병렬·능동/수동·형용사/부사 등)는 모든 문장에 최소 1개씩 빠짐없이 낸다. 없는 요소는 억지로 만들지 않고 `absent`에 적는다. 어휘·철자 구분(every day/everyday류)은 내지 않는다.
  - `shuffle`: 확인 테스트에 보여줄 순서(원문 문장 번호 1부터의 목록). 제자리에 남는 문장이 없게 섞는다(스크립트가 자동 검사).
  - `ko`: HWP 해석을 그대로 쓰지 않고 새로 쓴 모범 해석. `points`: 문법 포인트 설명.
  - 40번처럼 원문에 [요약문] 줄이 있으면 그 줄은 `sentences`에 넣지 않는다. 43~45번은 (A)~(D) 문단을 이어서 문장 단위로 나눈다.
- 여러 지문을 합칠 때는 `py 스크립트/수업자료_병합.py {시험} {번호1} {번호2} ...`(2026-09-28 추가, 2026-10-02 개정) — 각 `작업/{시험}_{번호}번_수업.json`을 다시 조립해 번호순으로 이어 붙이고 `결과/{시험}_수업자료_전체.pdf`(학생용) + `결과/{시험}_수업자료_전체_정답지.pdf`를 만든다. 41~42번처럼 번호에 물결이 있으면 인자는 `41-42`로 쓴다.
